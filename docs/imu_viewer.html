01 · GYROSCOPE

gyro = how fast it is turning

Each axis is a spin axis. A number is not an angle, it is a speed in degrees per second. Turn the board and the bar jumps; stop turning and it falls back to 0, even if the board stays tilted. Sign rule: point your right thumb along the + axis, your fingers curl in the + direction.

02 · ACCELEROMETER

accel = where gravity points, plus every push

Even lying still, the sensor feels about 9.8 m/s² on the axis that points up: the table pushes it up against gravity. Tilt the board and that 9.8 is shared between the axes. Shake it and extra pushes are added on top.

03 · THE KEY DIFFERENCE

Tilt and hold: gyro forgets, accel remembers

gyro answers “is it turning, and how fast?”

Quick and clean, and not fooled by shaking. But it only knows about change: a board held tilted at 30° reads 0. For a walking robot this is the fast signal for “I am starting to fall”.

accel answers “which way is down?”

Knows the tilt even when nothing moves. But every step, bump and shake is mixed into it. For a walking robot this is the slow signal for “I am leaning”.

The trained policy gets both, 50 times a second: 3 gyro numbers (rad/s) and 3 accel numbers (m/s²). The BNO085 also blends them itself into the orientation q that turns the 3D board above.

04 · TRY THIS

Five moves, one at a time

1. Leave it flat on the table.
gyro ≈ 0 on all axes. accel ≈ (0, 0, +9.8) if the chip side faces up. |a| on the green line.
Only gravity acts. Small offsets (like −0.6) mean the board or table is a few degrees off level.
2. Slowly raise the +x end about 30°, hold it.
While moving: gyro y goes negative. Holding: gyro back to 0, accel x ≈ +4.9, tilt x ≈ +30°, the bubble moves to +x.
sin(30°) × 9.8 = 4.9: part of gravity now falls on x.
3. Turn it flat on the table, a quarter turn to the left.
gyro z positive while turning. accel does not change. Turned z ≈ +90°.
Turning around the up axis does not change where gravity points, so only the gyro sees it.
4. Shake it quickly side to side.
accel and |a| jump far from 9.8. The tilt numbers become nonsense for that moment.
The pushes from your hand add to gravity. This is what walking does to the robot's accel.
5. Turn it upside down.
accel z ≈ −9.8, “upside down” shows. The 3D board flips.
Your robot's mount may be like this. The axis wizard finds out and fixes the signs.
05 · SENSOR AXES vs ROBOT AXES

These are the board's axes, not the robot's yet

The x, y, z here are printed on the BNO085 board. The simulation uses robot axes: x = toward the head, y = robot's left, z = up. The axis wizard in imu_test.py (key a) works out how the board is mounted and saves it to hardware_imu.json; from then on the Python tools convert every sample to robot axes.

How to use this page

  1. Flash hardware/esp32_imu_bridge to the ESP32 (once).
  2. Close every other program on COM4: imu_test.py, motion_test.py, the Arduino Serial Monitor.
  3. Open this file in Chrome or Edge (Web Serial does not work in Firefox or Safari).
  4. Click Connect ESP32, pick the COM4 port, click Connect. The ESP32 restarts, then data starts in about 2 s.
  5. Click Stop before running a Python tool again, so the port is free.

If the Connect button says Web Serial is not available, serve the page from the project folder and open it through localhost:

python -m http.server 8000
# then open http://localhost:8000/docs/imu_viewer.html

What the page sends: ? (ready check), S (IMU status), I about 50 times a second (one sample), R every 2 s (watchdog restarts). It never sends a servo command.
